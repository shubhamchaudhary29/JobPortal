## Frozen foundations

The following behavior is frozen: preserve it and avoid unrelated rewrites. Minimal extensions needed by a milestone remain allowed.

- Existing Adzuna cached ingestion.
- Mongo-only public job search.
- Typed Greenhouse/Lever adapters and normalization.
- Fingerprints, source identities, and application-URL preservation.

- Employer registry and independent schedules.
- Distributed leases, heartbeats, and cancellation checks.
- Adzuna lease configuration and lease-loss response.
- Existing security and Docker configuration.

## Post-completion correctness hardening

- Provider response structure and cancellation: Greenhouse accepts an empty board only as `{"jobs":[]}`; Greenhouse `{}`, JSON `null`, a missing `jobs` member, and empty/204 bodies, plus Lever JSON `null` and empty/204 bodies, are permanent `MALFORMED_RESPONSE` failures. The lease-valid signal now crosses retry and request-rate waits and is checked before each attempt and immediately before HTTP. Malformed or cancelled runs cannot write items or advance lifecycle missing state, interruptions retain the thread interrupt flag, and logs contain neither provider URLs nor response bodies.
- Application/cleanup exclusion: application creation atomically reserves the job before storing an application; cleanup atomically takes the mutually exclusive per-job claim before its final legacy-reference check and token-guarded delete. Inactive or reconciliation-pending imports reject new applications, stale cleanup claims are recoverable, existing applications remain readable, and recruiter jobs retain their previous behavior.
- Migration audit completeness: the bounded read-only audit now detects cross-document imported source-identity duplicates and both compatibility-field mismatch classes before unique-index creation. Its seeded harness proves clean acceptance, status `2` for each new anomaly category, and byte-for-byte unchanged job/conflict snapshots after every audit invocation.

## Phase 4 — Source expansion (India focus)

Phase 1–3 above are complete. Phase 4 grows job coverage, mainly for India, without weakening the frozen foundations. ### Source policy (applies to every Phase 4 milestone)

- Allowed: public company ATS job-board APIs (Greenhouse, Lever, Ashby, SmartRecruiters, Workable) and publisher/affiliate aggregator APIs (Adzuna, Jooble, Careerjet) used within their terms.
- Aggregator listings keep the provider's own redirect link as `applicationUrl` and show provider attribution wherever the job is displayed. Respect each provider's documented caching/retention rules; record them in `docs/provider-terms.md` before enabling the provider.
- Not allowed: LinkedIn, Naukri, Indeed, or any scraping that breaks a site's terms. JSearch (RapidAPI) is limited to local/manual testing and is never scheduled or enabled by default.
- API keys come from environment variables only, are never logged, and every new provider is disabled by default when its key is missing.
- Order: ATS growth first (best data, no quota), then dedup normalization (so more sources do not multiply duplicates), then the aggregator APIs, then Adzuna tuning, then the Mongo-backed registry.
